# 悟码AI v1.3.16

面向编程实验的自适应答辩与理解度评测平台。作品采用“浏览器Web Demo + LearnBuddy专家智能体”双入口：Web端呈现学生学习证据与教师诊断闭环，LearnBuddy通过只读技能与MCP查询同一份结构化数据。

## v1.3.16 LearnBuddy状态语义与UTF-8修复

- MCP明确拆分“教师待办队列、教师复核、学生学习、学生反馈”四类状态，避免把“需要巩固”误报为“教师尚未处理”；
- 空待办不再只返回裸数组，而是返回“状态=空、待办数量=0、当前没有尚未处理的教师任务”的确定性结论；
- 空字段和旧记录中未单独保存的结论不再返回裸`null`，并明确不得由此推断待复核或待反馈；
- LearnBuddy Skill规定教师待办只看队列，已复核但仍需巩固应表述为“已处理，但学生仍需巩固”；
- Windows下MCP标准输入、输出和错误流强制使用UTF-8，降低GBK/UTF-8乱码风险；
- 不改变数据库结构、历史记录、判题规则、网页Demo数据或MCP只读权限。

## v1.3.5 可靠判题与发布自检

- Docker运行容器显式使用`-i`保持标准输入，修复程序在容器内读不到隐藏测试输入、正确代码被误判WA或RE的问题；
- 新增覆盖真实Docker命令链路的回归测试，不再只验证宿主Python子进程的stdin；
- 启用代码验证时，教师必须配置至少3组隐藏测试和一份仅教师可见的参考答案；
- 发布或保存前，系统会用参考答案实际跑完隐藏测试和全部公开样例，任一CE、WA、TLE、RE、OLE或环境故障都会阻止保存；
- 直接把“求数组中的最大值”默认评分点用于其他题目时会出现高风险警告，教师必须修改或显式确认，确认状态会写入实验记录；
- 从旧版迁移而来的高风险实验仍可练习和判题，但修正配置前不会继续生成新的不可信AI答辩报告；
- 隐藏测试输入和预期输出上限提高到200万字符，正式判题输出限额会根据标准答案长度动态放宽，保存证据仍限制为2万字符预览；
- C++正式评测改用`-O2`编译，避免高难度算法因调试优化级别产生不公平TLE；
- AI提示标记“当前代码”或“历史代码·已失效”，新提示只继承同一代码版本的历史提示；
- AI初评、提示和答辩题会读取题目数据范围，不再把范围外输入直接当作正确性缺陷；
- 118项自动测试全部通过，覆盖Docker stdin、参考答案门禁、评分模板审查、大输出判定、提示版本和旧数据库迁移。

## 选择代码验证后端

### Docker隔离模式（推荐演示部署）

先安装并启动Docker Desktop，然后在PowerShell中执行：

~~~powershell
docker pull gcc:13-bookworm
docker image inspect gcc:13-bookworm
~~~

把`.env`中的设置改为：

~~~text
CODE_EXECUTION_ENABLED=true
CODE_EXECUTION_BACKEND=docker
DOCKER_COMMAND=docker
DOCKER_CPP_IMAGE=gcc:13-bookworm
CODE_EXECUTION_TIMEOUT_SECONDS=2
CODE_COMPILE_TIMEOUT_SECONDS=15
CODE_EXECUTION_MAX_OUTPUT_CHARS=4000
~~~

应用不会在学生提交时自动下载镜像，避免请求长时间卡住。完整检查和故障排查见`DOCKER_SETUP.md`。

### 本机g++兼容模式

先在PowerShell中检查编译器：

~~~powershell
g++ --version
~~~

如果能看到版本号，把`.env`中的设置改为：

~~~text
CODE_EXECUTION_ENABLED=true
CODE_EXECUTION_BACKEND=local
CXX_COMPILER=g++
CODE_EXECUTION_TIMEOUT_SECONDS=2
CODE_COMPILE_TIMEOUT_SECONDS=15
CODE_EXECUTION_MAX_OUTPUT_CHARS=4000
~~~

如果`g++ --version`找不到命令，可安装MinGW-w64并加入PATH，或者把`CXX_COMPILER`填写为`g++.exe`的完整路径。修改`.env`后重新启动Streamlit。

代码执行默认关闭。本机模式只适用于本人电脑上的受信任课堂演示，不应直接运行陌生人代码。Docker模式增加多项隔离限制，适合本项目评审演示和受控课堂环境；公开互联网部署仍应增加独立判题节点、身份认证、请求限流、审计和主机级监控。

## LearnBuddy接入架构

| 层级 | 实际职责 |
| --- | --- |
| 腾讯LearnBuddy | 赛事指定的交互平台，承载对话、Skill和连接器 |
| LearnBuddy平台当前模型 | 理解教师指令并组织最终回答；不是悟码AI自行调用的LearnBuddy API |
| 悟码AI教师Skill | 约束何时查询、输出结构、证据口径和隐私边界 |
| wuma-ai MCP连接器 | 只读查询本地SQLite数据库并返回精简结构化证据 |
| 悟码AI网页侧腾讯混元 | 生成答辩题、评价回答和生成理解度报告 |

因此，“使用LearnBuddy”和“悟码AI网页调用腾讯混元”是两条不同链路。比赛介绍不得把LearnBuddy说成自研大模型，也不得声称存在本项目可直接调用的LearnBuddy模型API。

## 腾讯混元配置（赛事展示推荐）

把`.env.example`复制为`.env`，填写：

~~~env
LLM_PROVIDER=hunyuan
LLM_PROVIDER_NAME=腾讯混元
LLM_API_STYLE=openai-compatible
LLM_API_KEY=你的腾讯混元密钥
LLM_BASE_URL=https://api.hunyuan.cloud.tencent.com/v1
LLM_MODEL=hunyuan-turbos-latest

也可以使用同义的腾讯混元专用变量：

LLM_PROVIDER=hunyuan

HUNYUAN_BASE_URL=https://api.hunyuan.cloud.tencent.com/v1
HUNYUAN_MODEL=hunyuan-turbos-latest
~~~

从旧版本复制的历史模型变量仍可被识别，便于先迁移数据库和配置；但侧栏会提醒切换，比赛截图、视频和现场演示应使用上面的腾讯混元配置。系统仍会在提示词中要求返回JSON，并校验返回结构。

## 当前MVP边界

- 当前只支持C++实验；
- 当前支持OJ式题面、公开样例、自定义运行及1至8组教师隐藏测试，但不是完整在线判题平台；
- local本机模式只面向可信演示；Docker模式已隔离网络和资源，但不是完整生产判题集群；
- 少量样例通过不代表程序对所有输入正确；
- 实验报告当前为文本填写，尚未解析Word或PDF附件；
- 学生入口按自行填写的姓名和学号隔离页面数据，但没有验证学生真实身份，尚未接入学校统一身份认证；
- AI诊断仅作为教师复核材料，不直接作为课程成绩。
