# 悟码AI v1.3.16：手动测试顺序与记录

先按“01_教师布置实验.md”发布实验，再按“02_学生答案与答辩参考.md”扮演学生。当前网页没有配套JSON一键导入功能，JSON和输入输出文件只用于复制与核对。

## 推荐测试顺序

| 顺序 | 测试内容 | 通过标准 |
| --- | --- | --- |
| 1 | 教师发布新实验 | 8组隐藏、3组公开参考答案自检全部通过，发布成功；两套权重各自合计100。 |
| 2 | 学生核对题面 | 输入输出、数据范围、公开样例和4项评分点完整；隐藏答案与隐藏输入输出不出现。 |
| 3 | 正确代码跑公开样例与自定义输入 | 公开3/3通过；自定义全负数输出-2，说明其只代表当前输入。 |
| 4 | 正确代码正式评测 | 隐藏8/8、客观代码100分；点击正式评测后先停留在提交页，另行进入答辩。 |
| 5 | 完成充分解释的答辩 | 问题结合本代码生成；评价引用实际回答；报告能回看各题与必要追问。 |
| 6 | 正确代码配错误回答 | 代码分仍100；评价能识别具体理解错误，教师能核查依据。AI分数不要求固定值。 |
| 7 | maximum初始化为0 | 隐藏通过5/8、客观60分；全负数公开样例失败；“全部通过”准入阻止答辩。 |
| 8 | 使用一次AI提示并修正代码 | 提示围绕当前代码缺陷，不给出隐藏输入输出；更换代码后旧判题及提示标识失效；新代码必须重新正式评测。 |
| 9 | 缺分号代码 | 显示CE与编译信息，不误报AC；不能进入默认答辩。 |
| 10 | 死循环代码 | 显示TLE，达到配置的时间限制后终止；页面可继续使用。 |
| 11 | 学生提交学习指导反馈 | 待处理反馈增加，教师“前往处理”定位正确学生与反馈；返回待办仍可继续选择。 |
| 12 | 教师回复与学生查看 | 保存回复后教师待办更新；学生能从任务中心打开回复，未读状态更新。 |
| 13 | 教师认可诊断 | 教师确认理解度同步为AI理解度；复核记录保存，学生端可查看。 |
| 14 | 教师要求理解不足者重答 | 学生出现重答任务；完成后显示第2轮、新报告待复核，原证据保留。 |
| 15 | 学习档案与阅读界面 | 累计记录与轮次含义分开；完整报告按需展开，切换后收起；图表横向文字与标题留有间距。 |
| 16 | 班级分析和CSV | 筛选当前实验后统计对应记录，导出内容与页面一致，不混入其他实验。 |

建议先做第1—7项，确认正常流程和“代码正确≠理解充分”这条核心行为；再做错误分支和反馈、重答闭环。

## 可选：测试不同答辩准入规则

主实验保留“全部通过”。如需比较另两种规则，另建测试实验，复制相同题面、样例和参考代码，避免改变主实验测试条件。

| 规则 | 测试方法 | 预期 |
| --- | --- | --- |
| 达到指定分数，阈值60 | 正式评测初始化为0的代码 | 客观60分，允许进入答辩；AI应围绕相关缺陷诊断，代码分不因答辩变成100。 |
| 达到指定分数，阈值65 | 同一错误代码 | 客观60分，低于阈值，应阻止进入答辩。 |
| 允许带错代码 | 同一错误代码 | 允许诊断答辩，仍保留客观60分；不能向学生泄露隐藏输入输出。 |

无论规则如何，环境不可用、验证未启用或尚未正式评测均不能作为有效代码结论据此放行。

## 可选：检查发布前自检和输入校验

- 新建未发布实验，将一个隐藏测试的预期输出故意写错：参考答案自检应失败，实验不能发布；恢复正确输出后再发布。
- 将评分点权重或隐藏测试分值合计改为99：应阻止保存并指出合计问题。
- 少于3组隐藏测试却启用验证：应阻止发布。
- 学生解题思路留空：应提示补充，保留已有输入。
- 学生选做实验报告留空：允许正式提交和答辩，不能仅因没交报告扣理解分。
- 正式评测后修改代码或学号：旧评测失效，必须重新评测。

## 记录模板

复现问题时，记录这些信息便于后续定位；不要记录或粘贴密钥。

```text
测试时间：
实验名称与编号：
测试学号：
测试项序号：
使用代码文件：
操作步骤：
预期结果：
实际结果：
页面错误提示：
对应提交编号与答辩轮次（如有）：
AI实际问题、学生实际回答与评价（如涉及）：
```

编译器诊断内容可能随g++版本不同；AI题目、追问和分数也会动态变化。判题的预期输出和客观60/100、100/100是确定的，答辩验收则以理解结论与原始证据是否一致为准。
